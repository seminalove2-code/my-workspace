# 월 1,000 자동화 시스템: 내가 없어도 결제부터 전달까지 이어지는 5단계 노하우
- 원본: 10번 / 91페이지 (PDF)
- 부제: 쉬는 날에도 결제되고, 이동 중에도 전달되는 운영 매뉴얼 / 지은이: 솔루션키 클래스
- 대상: 월 순수익 1,000만 원 경험자 또는 근접자(곧 시작할 사람도 가능). 한 달 안에 "자리 비움 시스템" 완성 목표.
- 범위: "무엇을 팔까"가 아니라 "어떻게 비워도 돌아가게 할까"만. 스레드 글쓰기·판매 퍼널·상세페이지·이메일 자동화는 앞선 책(다른 플레이북) 참조.
- 원본 내 미완성 자리표시자: [저자 입력: …] 7곳, [저자 확인: …] 1곳 — 아래 "자리표시자" 섹션에 원문 그대로 기록.

## 한 줄 요약
반복 작업은 자동으로, 사람 일은 모아서, 고장은 알림으로 — 분류(자동화할 것/남길 것) → 연결(결제 후 10분 무인화, 시차 응대 약속) → 감시(5가지 알림 + 장애 대응 5단계) → 리듬(제작일·점검일·비움일) → 이동(클라우드·복구코드·비상 시나리오) 순서로 "자리 비움 시스템"을 만든다.

## 핵심 공식 / 프레임워크

### 1) 자리 비움의 정의 (3조건)
"내가 자리를 비운 사이에도, 정해진 일은 정해진 대로 이루어지고, 이상이 생기면 내가 먼저 알 수 있는 상태"
- 반복되는 일은 사람 없이 돌아가요.
- 사람이 필요한 일은 미뤄도 되는 시간대에 모아서 처리해요.
- 고장 나면 알림이 와서 내가 먼저 알아요.
- 쉬는 날이 불안한 이유는 대부분 세 번째 조건(알림)이 없기 때문.

### 2) 자리 비움 시스템 5단계 지도 (순서 중요)
| 단계 | 이름 | 핵심 질문 | 챕터 |
|---|---|---|---|
| 1 | 분류 | 자동화할 것과 내가 남을 것은 무엇인가요? | 2 |
| 2 | 연결 | 결제부터 응대까지 시차와 무관하게 이어지나요? | 3 |
| 3 | 감시 | 고장 나면 내가 먼저 알 수 있나요? | 4 |
| 4 | 리듬 | 일주일을 어떻게 나눠 쓰고 있나요? | 5 |
| 5 | 이동 | 장소가 바뀌어도 같은 속도로 돌아가나요? | 6 |
- 앞 단계가 약하면 뒤가 무너짐: 분류 없이 연결 → 불필요한 자동화 증가 / 감시 없이 이동 → 해외에서 장애.
- (+ 챕터 7: 유지와 확장)

### 3) 분류 기준 3가지 (챕터 2)
- 반복성: 한 달에 몇 번 같은 순서로 하는가. 월 2~3회는 자동화 비용이 더 클 수 있음. 주 5회 이상부터 후보.
- 실수 비용: 잘못되면 얼마나 큰 문제인가(파일 미전달 → 환불, 결제 확인 지연 → 신뢰 하락). 높으면 자동화하되 반드시 실패 알림.
- 사람 온도: 고객에게 "나를 챙겨준다"는 느낌을 주는 일인가(구매 직후 인사, 불만 문의, 특이 요청 → 템플릿이면 거리감).
- 규칙: 반복성 높고, 실수 비용 관리 가능하고, 사람 온도 낮을수록 자동화 적합.
- 핵심 질문: "이 일을 내가 안 하면 누가 불편한가요?" → 내가 불편 = 자동화 후보 / 고객이 불편 = 신중.
- 사람이 직접 하는 일 비율: 전체의 20~30%를 출발 기준점(정답 아님, 고객 반응 보고 조정).
- 가장 먼저 자동화할 일 = "시간이 가장 많이 들고, 실수해도 피해가 작고, 고객이 사람을 기대하지 않는 일".
- 판정 유형: 자동화 / 자동화 + 실패 알림 / 템플릿 + 사람 한 줄 추가 / 템플릿 자동 + 예외는 사람 / 사람이 직접 / AI 초안 + 사람이 결정 / 자동 집계 + 사람이 확인 / (반복성 낮음 →) 체크리스트.
- 원칙: 템플릿은 쓰되, 구매자가 질문·특이사항을 남기면 반드시 사람이 직접 답한다.

### 4) 연결: 결제 후 10분 설계 (챕터 3)
- 결제 후 10분 안에 고객이 받아야 할 3가지: 결제 확인, 상품 접근 방법, 문의 방법 → 사람 없이 전달되면 흐름의 80% 안정.
- 고객 흐름: 상품 페이지 → 결제 → 결제 완료 안내 → 파일/강의 링크 수령 → 읽다가 궁금 → 문의 → 답변 → 후기. 각 칸에 "지금 누가 처리하나요?"(플랫폼 자동 / 내 자동화 / 내가 직접). 직접 칸은 보통 파일 전달 확인·문의 답변에 몰림.
- 시차: "항상 바로 답한다" 포기 → "언제까지 답한다" 약속. 응대 3구간: 즉시 자동 응답 / 반나절 안 사람 / 하루 안. 상품 페이지와 구매 완료 안내에 미리 명시. "길게 약속하고 지키는 쪽이 짧게 약속하고 어기는 쪽보다 신뢰."
- FAQ 우선: 지난 한 달 문의를 유형별로 묶기(보통 3~4유형이 대부분: 파일 미수령, 사용법, 결제·영수증) → 답변 한 번 잘 써서 3곳에 연결(상품 페이지 안내 영역, 구매 완료 안내 문구, 문의 접수 자동 응답).

### 5) 감시 (챕터 4)
- 감시할 5가지: 결제 성공·실패 / 자동 전달 성공 / 문의 대기 시간 / 계정 상태와 노출 급락 / 플랫폼 공지.
- 알림은 울려야 할 것만(너무 자주 울리면 무시하게 됨). 기존 플랫폼·결제·메신저 알림 설정부터 조합.
- 장애 대응 5단계: 인지(5분) → 분류(5분) → 임시 조치(15분) → 복구(당일) → 기록(당일). 가장 중요한 건 3단계: 원인 파악보다 고객 보호 먼저.
- 장애 일지 5줄. 석 달 쌓이면 반복 원인 = 다음 손볼 자동화.
- 분기 1회 집중도 점검: 판매 경로 한 플랫폼 의존? 고객 연락처·구매 기록을 내가 접근 가능한 곳에 따로 보관? 계정 로그인이 한 사람 휴대폰 인증에만 묶임? → "그렇다"면 분산이 다음 달 과제.
- 계정 정지 교훈: 한 곳에 몰아둔 것은 한 번에 사라짐 / 대응 순서 미리. 댓글 표현 다양화, DM 발송량 조절, 글 2시간 간격, 계정 3개 분산.

### 6) 리듬: 일주일 3칸 (챕터 5)
- 제작일: 새로 만드는 날(기획·원고·스레드 초안). 주 2일 정도로 시작. 알림 끄고 문의도 안 봄(결제 실패·자동 전달 실패 알림만 켬).
- 점검일: 알림 설계표대로 결제·전달·문의·유입 확인, 사람 답변 몰아서. 주 1~2일. 알림 전체 켬.
- 비움일: 아무것도 안 하는 날. 긴급 알림만("이미 결제한 고객에게 영향이 있는 일"로 한정). 노마드는 이동·휴식·탐색.
- 원칙: 같은 종류의 일은 한곳에 몰아서. 한 번 정한 칸은 최소 한 달 유지. 비움일 하루는 반드시.
- 의욕 저하: 숫자는 매일이 아니라 주간 단위로 / 목표를 극단적으로 작게("오늘은 클로드에게 소재 하나만 물어보기") / 제작일을 점검일로 바꿔도 됨(주간 총량이 같으면 OK). "리듬은 감옥이 아니라 기본 설계도."
- 제작 순서(40시간 → 8시간): AI에게 목차 구조 초안 → 각 항목에 실제 경험·디테일 → 전체 톤 정리.
- 휴대폰 집중 모드/방해 금지로 칸마다 알림 일괄 전환.

### 7) 이동 (챕터 6)
- 이동 전 체류 환경 4가지: 인터넷, 전원, 작업 공간, 시차.
- 장비 2원칙: 모든 자료 클라우드 / 최소한의 대체 수단(휴대폰만으로 결제 확인·간단 응대).
- 클라우드에 둘 것: 원고·상품 파일, 고객 응대 템플릿, 계정 정보와 복구 코드.
- 인터넷 이중화: 숙소 와이파이 + 휴대폰 핫스팟. 현지 유심/이심은 국가·통신사별 확인.
- 2단계 인증: 해외 새 위치 로그인 차단 대비 → 출발 전 복구 코드 안전 보관.
- 세무(일반 정보, 세무사·국세청 확인 필수): ① 사업자 등록·통신판매업 신고(해외 체류 시 주소지·연락처·우편물) ② 종합소득세 보통 매년 5월, 부가세 신고 시기; 해외에서 홈택스·인증서 사용 가능 여부 ③ 거주자/비거주자(체류 기간만 아니라 생활 근거·가족·자산 종합 판단; 6개월 이상 체류 계획이면 출발 전 세무사 상담) ④ 체류 국가 규정(방문 목적·체류 자격별 현지 근로 허용 여부, 공식 안내 확인 — 책은 다루지 않음).

### 8) 유지와 확장 (챕터 7)
- 월 순수익 역산: 필요 매출 = 목표 순수익 ÷ (1 − 비용 비율) → 필요 판매 건수 = 매출 ÷ 객단가 → 하루 건수 = ÷ 30.
- 월간 지표 대시보드 6가지(비움일 사용 일수가 핵심).
- 확장 판단 4질문 → 모두 "네"면 확장, 하나라도 "아니오"면 유지 우선.
- 자동화 졸업 기준 3가지.
- 수익 흔들릴 때 재정비 5단계(장애처럼 바로 고칠 원인부터 배제).

## 실행 절차 (단계별)
[사용자] = 사용자 정보·계정·설정 필요, [Claude] = Claude가 생성 가능 (부록 5 프롬프트 활용)

0. 자가진단
   1. [Claude] 자가진단 8문항을 사용자에게 묻고 "네" 개수 집계.
   2. 6개 이상 → 점검용으로 / 3~4개 → 챕터 3·4(연결·감시)부터 / 2개 이하 → 순서대로 한 단계씩. 한 달 뒤 재진단.

1. 1주차 — 분류
   1. [사용자] 지난 7일 동안 반복한 일을 최소 10가지 나열(5분).
   2. [Claude] 부록 5 프롬프트 1로 분류표 작성(반복 빈도·실수 비용·사람 온도 → 판정 + 이유 한 줄).
   3. [Claude] "사람이 직접" 비율 확인(20~30% 기준), 분류표 점검 질문 4가지 적용, 애매한 항목은 FAQ 반반/체크리스트/점검일 몰아서 처리로 판정.
   4. [사용자] "사람이 직접" 항목 하나를 이번 주 일부러 직접 챙기기. 첫 자동화 대상 1개 선정(권장: 결제 후 파일 전달).
   완료 기준: 분류표 한 장 완성.

2. 2주차 — 연결
   1. [사용자] 판매 플랫폼 설정 화면에서 파일 자동 전달·구매 완료 알림 확인. 부족하면 결제 자동화 서비스 병행.
   2. [Claude] 고객 흐름 8칸 표를 만들어 칸별 처리 주체 기입 도움.
   3. [Claude] 응대 구간표(문의 유형 5종)와 응대 시간 약속 문구 작성 → [사용자] 상품 페이지·구매 완료 안내에 반영.
   4. [Claude] 자동 안내 문구 3종({고객이름} 등 변수 채우기)과 FAQ(지난 한 달 문의를 3~4유형으로) 작성 → 3곳 연결.
   5. 응대 톤 가이드로 자동·수동 답변 톤 통일.
   6. [사용자] 시험 구매(낮은 가격/테스트 상품) → 연결 점검표 5항목 확인. 미통과 1개 이번 주 수정.
   완료 기준: 연결 점검표 통과.

3. 3주차 — 감시
   1. [Claude] 알림 설계표 5줄 작성 → 부록 5 프롬프트 2로 구멍/과다 알림 점검.
   2. [사용자] "결제 실패", "자동 전달 실패" 알림을 이번 주 실제로 오도록 설정(기존 서비스 알림부터).
   3. [Claude] 장애 대응 5단계 + 장애 일지 틀을 노션/휴대폰 저장용으로 제공. 장애 발생 시 프롬프트 4로 일지 정리.
   4. 분기 1회 집중도 점검 질문 일정 등록.
   완료 기준: 결제·전달 알림 실제 수신.

4. 4주차 — 리듬 + 이동
   1. [Claude] 사용자 생활·체류 시차에 맞춰 주간 3칸 표 작성(비움일 1일 이상 필수), 칸별 알림 정책, 제작일 시간표.
   2. 매주 마지막 점검일 "주간 마감 10분" → [Claude] 프롬프트 5로 다음 자동화 후보 3개.
   3. [사용자] 클라우드 백업·2단계 인증 복구 코드 저장(이번 주 안). 이동 계획 있으면 [Claude] 프롬프트 6으로 체크리스트, 출발 7일 전 체크리스트, 비상 시나리오 3종 휴대폰 저장, 자리 비움 안내 문구(프롬프트 3).
   4. 도시·숙소 5항목 1~5점 평가, 낮은 항목마다 대비책 1개.
   완료 기준: 비움일 하루 확보.

5. 매월 — 유지·확장
   1. [Claude] 월간 지표 대시보드 6항목(실제 숫자; 모르는 칸 = 다음 달 최우선 개선).
   2. 월 순수익 역산 계산(최근 3개월 실제 비용 비율 사용).
   3. 월간 회고 8문항.
   4. 확장 판단 4질문 → 확장/유지 결정. 자동화 졸업 기준 점검.
   5. 수익 하락 시 재정비 5단계 순서대로.

### 알림 설계표 (챕터 4 예시; 부록 2 빈 양식 행: 결제 실패 / 자동 전달 실패 / 문의 대기 시간 / 유입 급락·계정 경고 / 플랫폼 공지)
| 항목 | 알림 방법 | 알림 기준 | 확인 시점 |
|---|---|---|---|
| 결제 실패 | 휴대폰 푸시 | 실패 1건이라도 발생 | 즉시 |

| 문의 대기 | 이메일 요약 | 약속 시간의 80% 경과 | 점검 시간 |
| 유입 급락 | 주간 리포트 | 전주 대비 크게 하락 | 주 1회 점검 |

## 흔한 실수 / 문제 해결
- 시간을 더 쓰는 방식(잠 줄이기, 쉬는 날 판매 현황 확인, 대시보드 새로고침) → 수익이 늘수록 한계.
- 구조가 사람 손에 달려 있으면 성장 = 과로.
- 무작정 자동화부터: ① 사람 온도가 필요한 부분까지 자동화(후기 요청 "너무 정형화된 느낌이라 조금 아쉬웠다") ② 고장 나도 아무도 모름.
- 도구부터 고르기 → 먼저 자동화할 일/남길 일을 정할 것.
- "사람이 직접" 개수가 너무 적음 = 과한 자동화 / 너무 많음 = 후보 발굴 부족.
- "곧 답변드리겠습니다" 같은 막연한 약속, 긴 인사말, 변명부터 꺼내기, 같은 감사 문장 반복.
- 환불·불만에 템플릿 답변 금지.
- 알림 과다 → 무시하게 됨. 울려야 하는 것만.
- 장애 시 원인부터 찾기 → 고객 보호(수동 전달) 먼저.
- 기록 생략 → 같은 문제 재발 시 해결 시간 증가.
- 작업을 하루에 조금씩 나눠 하기 → 매번 머리를 새로 켜야 해서 느림.
- 주간 칸을 자주 바꾸기 → 혼란.
- 해외 로그인 차단 시 복구 코드 없음 → 계정 접근 불가.
- 이동 당일 몰아서 준비 → 누락.
- 수익 하락 시 당황해서 상품 추가·가격 변경 → 원인 파악 불가.
- 시스템 흔들릴 때 확장 → 응대·장애 동반 증가.
- 자동화 끝없이 만들기 → 졸업 기준으로 함정 회피.

## FAQ 요점 (부록 6)
- 자동화 하나만 먼저? → 결제 후 파일 전달(실수 비용 가장 높고 한 번 만들면 계속 사용).
- 자동화 도구는 유료여야? → 아니요. 판매 플랫폼·결제 서비스 기본 알림만으로 시작 가능.
- 비움일에 정말 아무것도? → 긴급 알림만 켜고 쉬는 게 목표. 알림 설정이 제대로면 가능.
- 알림이 너무 많이 울리면? → 기준을 높이고 고객 피해 있는 알림만 즉시.
- 문의가 갑자기 몰리면? → 접수 확인 자동 응답 먼저 켜고 점검일에 우선순위대로.
- 혼자인데 대응 순서까지? → 혼자라서 더 필요. 당황한 순간에 순서를 새로 만들 수 없음.
- 해외 세금? → 일반 정보만 확인, 개인 상황은 세무사와.
- 월 1,000만 원이 아직 멀면? → 순서는 수익 크기와 무관. 지금 규모에서 한 단계씩.

- [저자 입력: 노마드로 지내기 시작했을 때 가장 먼저 부딪힌 불편함이나 불안을 한두 문장으로 적어주세요.] (챕터 1)
- [저자 입력: 이동 중이거나 시차가 다른 곳에 있을 때 응대가 꼬였던 경험, 그리고 그 뒤에 바꾼 규칙을 적어주세요.] (챕터 3)
- [저자 입력: 지금까지 가장 크게 겪은 자동화 장애 한 가지와 어떻게 대응했는지 적어주세요.] (챕터 4)
- [저자 입력: 현재 쓰고 계신 주간 루틴이 있다면, 요일별로 어떤 일을 하는지 간단히 적어주세요.] (챕터 5)
- [저자 입력: 지금까지 지내본 곳, 체류 기간, 그곳에서 가장 좋았던 점과 가장 불편했던 점을 적어주세요.] (챕터 6)
- [저자 입력: 지금 현재 비움일을 실제로 며칠 쓰고 있는지, 월 1,000만 원을 유지하는 데 가장 중요했던 원칙 한 가지를 적어주세요.] (챕터 7)
- [저자 확인: 월 1,000만 원 달성 시점과 현재 거주·체류 방식을 최종본에서 확인해주세요.] (저자 소개)
- 이 자리들은 사용자가 이 책으로 자기 콘텐츠를 만들 경우 사용자 본인의 경험으로 채워야 하는 칸이기도 함. Claude가 지어내지 말 것.

## 스토리 요약 (압축)
- 직장인 퇴근 후 2~3시간 → 스레드·AI 전자책·크몽/래피드 판매. 판매가 늘수록 더 묶임.
- 후기 요청 과잉 자동화 → "정형화" 피드백 → 사람 온도 원칙. 1만 팔로워 직전 계정 정지 → 감시·분산 원칙. 40시간 → 8시간 제작 → 리듬 원칙.
- 에필로그: "자동화는 일을 없애는 기술이 아니라, 내 시간과 마음을 지키는 기술." 다음 행동: 지난 7일 반복한 일 10가지 적기(5분).
