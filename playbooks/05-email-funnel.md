# AI 이메일 자동화 바이블: 구독자 50명으로 시작해 자는 동안에도 억대 매출 펀널 만드는 4단계 공식
- 원본: 5번 / 100페이지 (PDF)
- 주 도구: 스티비(Stibee) + 가비아(도메인/DNS)
- 주의: 이 책에는 AI 프롬프트 원문이 없음. 실행은 스티비 설정 + 이메일 작성 원칙 중심. 아래 "프롬프트 원문" 섹션 참고.

## 한 줄 요약
SNS 팔로워는 플랫폼 것, 이메일 리스트는 내 것 — 도메인 인증으로 "일단 도착"시키고(도달), 세그먼트+3단계 웰컴 시퀀스로 관계를 쌓고(공감), 제목 A/B 테스트와 클릭률로 다듬고(정교화), 발송 예약·반응 기반 자동화·리스트 헬스 관리로 주 40분 운영(지속)하는 "스티비 4단계 자동화 공식".

## 핵심 공식 / 프레임워크

### 1) 스티비 4단계 자동화 공식: 도달 → 공감 → 정교화 → 지속 (순환 사이클)
| 단계 | 영문 | 하는 일 | 대표 성과 |
|---|---|---|---|
| 1단계 도달 | Deliver | SPF·DKIM·DMARC 도메인 인증으로 받은편지함에 "일단 도착"하게 | 오픈율 15% → 28% (약 2주 후) |
| 2단계 공감 | Relate | 세그먼트로 구독자 나누기 + 웰컴 시퀀스로 첫인상 설계 | 첫 구매 전환율 3% → 11% |
| 3단계 정교화 | Refine | 감이 아니라 테스트로. 제목 A/B, 오픈율+클릭률로 콘텐츠·제목 다듬기 | 오픈율 최종 38% |
| 4단계 지속 | Sustain | 발송 예약, 반응 기반 자동 후속 메일, 리스트 헬스 관리 | 업무 주 5시간 → 40분 |
- 순서를 건너뛰지 말 것: "도달이 안 되는데 정교화부터 신경 쓰면 소용없고, 관계도 없는데 자동화부터 하면 빈 시스템만 돌아가는 셈."
- 한 번 완성이 아니라 계속 도는 사이클. 구독자 증가 시 세그먼트 재점검, 웰컴 시퀀스 업데이트, 새 가설로 테스트.
- 절대적 정답이 아닌 틀: 분야·구독자 특성에 따라 순서·비중 조정.

### 2) 도메인 인증 3종 (도달)
- SPF (Sender Policy Framework): "이 도메인에서 메일을 보낼 수 있는 서버는 어디어디다" 미리 등록. (비유: 우리 집 우편물은 이 우체국에서만 발송한다고 신고)
- DKIM (DomainKeys Identified Mail): 메일에 디지털 서명. 내용 조작 시 서명이 깨짐. (비유: 봉투 도장)
- DMARC (Domain-based Message Authentication, Reporting & Conformance): SPF·DKIM 상위 규칙. 검사 실패 메일을 스팸함/거부/통과 중 어떻게 처리할지 도메인 주인이 정함.
- DMARC 운영: 처음엔 관찰 모드 p=none → 문제없음 확인 후 단계적 강화. 처음부터 reject로 설정하면 정상 메일까지 막힘(저자 시행착오).

### 3) 세그먼트 3기준 (공감)
1. 가입 경과 기간별: 신규 = "저를 소개하는" 내용 / 오래된 구독자 = 깊이 있는 정보·프로모션
2. 관심사·행동 이력별: 특정 링크 클릭 이력 있음 = 더 구체적인 정보 / 클릭 없음 = 가볍고 흥미 끄는 콘텐츠
3. 구매 여부별: 구매 고객 = 감사 + 재구매 유도 / 잠재 고객 = 신뢰 쌓는 정보성 콘텐츠
- 최소 3개 이상 세그먼트가 효과적. 단, 10개 이상은 관리 불가 → 3~4개 큰 그룹이 적정.
- 처음 시작은 딱 2그룹(신규/기존 또는 구매/미구매) → 두세 개 기준으로 시작해 점차 정교화.
- 원칙: "모두에게 보내는 건 사실 아무에게도 제대로 보내지 않는 것과 같다."

### 4) 3단계 웰컴 시퀀스 (공감)
| 단계 | 발송 시점 | 목적(한 통에 하나) | 내용 |
|---|---|---|---|
| 1단계 | 가입 직후 | 소개와 공감 | 내가 어떤 사람인지, 왜 이 뉴스레터를 시작했는지, 구독자가 겪을 법한 고민에 공감. 판매 이야기 전혀 없음. "당신이 여기까지 온 이유를 저는 알아요" 느낌 |
| 2단계 | 가입 2~3일 후 | 가치 증명 | 실제로 어떤 도움을 줄 수 있는지, 어떤 노하우·정보가 있는지 구체적 예시로. 직접 판매보다 "이 사람 진짜 도움이 되는구나" |
| 3단계 | 가입 5~7일 후 | 자연스러운 제안 | 처음으로 제품·서비스 소개 |
- 흐름: 소개(공감) → 가치 증명 → 자연스러운 제안.
- "한 통에 하나의 메시지만 담기" 원칙.
- 제목: 정기 뉴스레터(궁금증·정보성)와 달리 개인적이고 다정한 제목. 예: "안녕하세요, 저를 소개할게요".
- 하루 간격 3통 연속 → 2번째부터 오픈율 급락(피로감). 간격은 분야별로 데이터 보고 조정.
- 익숙해지면 "특정 메일 열람 여부"에 따른 분기 로직 추가(스티비 자동화 지원). 단순 구조로 시작.
- 통 수는 정답 없음(2통~5통 이상). 흐름이 핵심.

### 5) 제목 A/B 테스트 원칙 (정교화)
- "발송 전에는 무조건 제목 최소 두 개를 만들고 테스트한다."
- 두 제목은 확실히 다른 접근이어야 함(예: 숫자 강조형 vs 질문형). 비슷한 제목 두 개는 유의미한 차이 안 남.
- 한 번 결과로 단정 금지. 여러 번 반복해 패턴 확인(이슈·요일 등 변수 있음).
- 오픈율 = 제목의 매력도 / 클릭률 = 콘텐츠의 실제 가치. 클릭률을 더 중요하게.
- 과장된 제목 → 오픈율↑, 클릭·구매↓(낚시). "과장하지 않되, 궁금증은 유발하는 선".
- 저자 구독자 패턴(일반 법칙 아님): 자극적 제목보다 구체적 숫자·정보 제목, 질문형보다 단정적 문장 제목 반응이 좋음.
- 발신자 이름 테스트: 저자는 개인 이름 > 브랜드명(오픈율 조금 더 높음). 발송 시간대도 테스트 가능.

### 6) 자동화 3종 (지속)
1. 발송 예약: 며칠 전 미리 완성해 예약.
2. 반응 기반 자동화: 특정 링크 클릭자에게 며칠 후 관련 후속 메일 / 오래 안 연 구독자에게 리마인드 메일.
3. 리스트 헬스 관리: 최근 3개월 이상 한 번도 안 연 구독자 = "휴면" 분류 → 재참여 메일("저희 소식 계속 받아보실래요?") 1회 → 반응자는 활성 복귀, 끝까지 무반응은 정기 발송 리스트에서 제외(삭제 대신 별도 분리 보관).
- 자동화 불가/금지 영역: 콘텐츠 기획, 핵심 메시지 → 사람이 직접.
- 자동 메일 문구도 "그 순간 직접 챙겨 보낸 것처럼" 자연스럽게 다듬기("자동 티가 난다" 피드백 방지).
- "자동화하되, 정기적으로 점검한다": 월 1회 자동화 규칙 유효성 점검(종료된 프로모션 안내 사고 방지).

## 실행 절차 (단계별)
[사용자] = 사용자 직접/정보 필요, [Claude] = Claude가 생성·안내 가능

### 0. 시작 (챕터 1)
1. [사용자] 스티비 가입, 첫 뉴스레터 발행지 만들기(구독자 0명이어도 OK).
2. [사용자] "왜 이메일을 시작하려는지" 이유 한 줄 → [Claude] 함께 정리.
3. [사용자] 내가 직접 소유한 채널이 있는지 점검.

### 1. 도달 (Deliver)
1. [Claude] 먼저 진단: 지인/다른 계정(특히 평소 왕래 없는 새 계정)으로 최근 뉴스레터가 스팸함에 있는지 확인하도록 안내. 네이버·다음·지메일 등 여러 메일 서비스에서 골고루 테스트.
2. [사용자] 도메인 보유 확인. 없으면 가비아 등에서 구매(무료 메일 주소로는 대량 발송 인증이 사실상 불가).
3. [사용자] 스티비 관리자 → "발신 도메인 인증" 메뉴에서 값 확인. 보통 3가지 값 제공:
   - SPF용 TXT 레코드 값
   - DKIM용 CNAME 또는 TXT 레코드 값
   - (필요 시) DMARC 정책용 TXT 레코드 값
4. [사용자] 도메인 업체(가비아·후이즈)의 DNS 관리 페이지에 그대로 붙여넣기. 레코드 타입(TXT/CNAME) 정확히, 값 앞뒤 공백·따옴표 오류 주의. 한 글자도 틀리지 않게 복사.
5. DMARC는 p=none(관찰 모드)으로 시작 → 문제없으면 단계적 강화.
6. 반영 대기: 보통 몇 분~몇 시간, DNS 전파 최대 24~48시간.
7. 스티비 "인증 확인" 버튼 클릭 → MXToolbox로 각 레코드 정상 확인.
8. 오픈율은 1~2주에 걸쳐 서서히 개선(즉시 X). 이 시기 발송 빈도를 늘리지 말 것.
9. 유지: 분기 1회 MXToolbox 점검(도메인 갱신·이전·호스팅 변경 시 레코드 누락 가능).

### 2. 공감 (Relate) — 세그먼트
1. [사용자] 현재 리스트를 2그룹으로(신규/기존 또는 구매/미구매). [Claude] 각 그룹에 필요한 메시지 한 줄씩 제안.
2. 스티비 "주소록"에서 태그/그룹 설정. 가입 시점 자동 태그, 특정 링크 클릭 시 태그 부여 자동화 규칙 설정.
3. 운영하며 3~4그룹(가입 기간·관심사/행동·구매 여부)으로 확장. 행동 이력(가입일, 반응 콘텐츠, 구매)을 꼼꼼히 기록.
4. 반응 좋은 그룹(특정 주제 클릭 이력)에는 비슷한 주제 후속 콘텐츠.

### 3. 공감 (Relate) — 웰컴 시퀀스
1. [사용자] 자기 소개·뉴스레터 시작 이유·구독자 고민·노하우 예시·제안할 제품 정보 제공 (본인 경험 필수).
2. [Claude] 3통 초안 작성(1통 1목적): 1) 가입 직후 소개·공감(판매 언급 없음), 2) 2~3일 후 가치 증명(구체 예시), 3) 5~7일 후 자연스러운 제안. 제목은 개인적·다정한 톤. (책의 "AI로 초안 → 내 경험과 목소리로 다듬기" 방식)
3. [사용자] 스티비 "자동화" → 트리거: 구독자 가입 → 간격 설정해 순차 발송.
4. 데이터 보고 간격 조정. 익숙해지면 1통 열람 여부로 2통 분기.

### 4. 정교화 (Refine)
1. [Claude] 매 발송마다 확실히 다른 접근의 제목 2개 이상 생성(예: 숫자 강조형 vs 질문형/단정형). 과장 금지, 내용과 일치.
2. [사용자] 스티비 발송 화면에서 제목 테스트 선택 → 전체의 일부(예 20~30%)를 무작위 2그룹으로 → 정해진 시간(보통 몇 시간) 오픈율 비교 → 승자 제목이 나머지에게 자동 발송.
3. 오픈율 + 클릭률 함께 기록(구글 스프레드시트 주차별). 여러 번 반복해 패턴 확인.
4. 발신자 이름(개인명 vs 브랜드명), 발송 시간대도 테스트.

### 5. 지속 (Sustain)
1. 발송 요일·시간 고정(구글 캘린더에 콘텐츠 마감일·발송일 등록). 며칠 전 완성 → 예약 발송.
2. 반응 기반 자동 후속 메일 1개 이상 세팅(링크 클릭 → 며칠 후 관련 메일; 장기 미오픈 → 리마인드).
3. 휴면(3개월+ 미오픈) 분류 → 재참여 메일 → 무반응은 분리.
4. 월 1회 자동화 규칙 점검, 분기 1회 휴면 구독자 정리, 분기 1회 도메인 인증 점검.
5. 반복 작업 하나를 골라 자동화로 대체 가능한지 매주 확인.
6. 현재 4단계 중 어디인지 점검 → 다음 채울 단계 하나 정하기.

### 정기 루틴 요약
- 매주: 정해진 요일·시간 발송, 제목 2개씩 준비(A/B)
- 매월: 자동화 규칙 점검
- 분기: 리스트 정리(휴면), MXToolbox 도메인 인증 점검

## 프롬프트 원문
- 이 책에는 AI 프롬프트/템플릿 원문이 없음.
- 책의 AI 활용 지침(부록 도구 8번): "뉴스레터 초안 작성이나 제목 아이디어 브레인스토밍에 활용 … 초안을 AI로 뽑아본 다음, 제 실제 경험과 목소리를 얹어서 다듬는 방식".
- 책에 나온 메일/제목 문구 원문(그대로 사용 가능):
```
웰컴 시퀀스 1단계 제목 예: "안녕하세요, 저를 소개할게요"
휴면 재참여 메일 문구: "저희 소식 계속 받아보실래요?"
1단계 메일 톤: "당신이 여기까지 온 이유를 저는 알아요"
```

### 챕터 2 (도달 진단)
- [ ] 지인 계정으로 내 뉴스레터가 스팸함에 있는지 확인했다
- [ ] 발송 성공과 실제 수신함 도착이 다른 개념이라는 걸 이해했다
- [ ] 네이버, 다음 등 여러 메일 서비스에서 골고루 테스트해봤다

### 챕터 3 (도메인 인증)
- [ ] 내 도메인이 있는지, 없다면 마련할 계획을 세웠다
- [ ] 스티비의 발신 도메인 인증 메뉴에서 필요한 값을 확인했다
- [ ] DNS에 값을 등록한 후 MXToolbox 등으로 인증 상태를 점검했다

### 챕터 4 (세그먼트)
- [ ] 구독자를 최소 두 그룹으로 나눠봤다
- [ ] 각 그룹에 어떤 메시지가 필요한지 정리해봤다
- [ ] 스티비의 태그/그룹 자동화 규칙을 확인해봤다

### 챕터 5 (웰컴 시퀀스)
- [ ] 3단계 웰컴 시퀀스의 각 단계 목적을 정리했다
- [ ] 각 메일 사이 발송 간격을 정했다
- [ ] 스티비 자동화 기능으로 시퀀스를 세팅해봤다

### 챕터 6 (A/B)
- [ ] 다음 발송 제목을 두 개 이상 준비했다
- [ ] 스티비의 A/B 테스트 기능으로 발송해봤다
- [ ] 오픈율뿐 아니라 클릭률도 함께 확인했다

### 챕터 7 (자동화)
- [ ] 발송 예약 기능을 사용해봤다
- [ ] 반응 기반 자동 후속 메일을 하나 이상 세팅했다
- [ ] 휴면 구독자를 분류하고 재참여 메일을 보내봤다

### 챕터 8 (공식 점검)
- [ ] 지금 내가 4단계 중 어디에 있는지 점검했다
- [ ] 다음으로 채워야 할 단계 하나를 정했다
- [ ] 이 공식을 나만의 상황에 맞게 조정할 부분을 생각해봤다

### 오늘의 실천 미션 (원문 요지)
- [ ] Ch1: 스티비(또는 원하는 툴)에 가입하고 첫 뉴스레터 발행지 만들기
- [ ] Ch2: 지인/다른 계정으로 최근 뉴스레터가 스팸함에 있는지 확인
- [ ] Ch3: "발신 도메인 인증" 메뉴를 찾아 필요한 항목 확인

- [ ] Ch5: 스티비 자동화 기능 열고, 3단계 웰컴 시퀀스 단계별 주제 한 줄씩
- [ ] Ch6: 다음 발송 전 제목 후보 2개로 A/B 테스트 발송
- [ ] Ch7: 가장 반복적인 작업 하나를 스티비 자동화로 대체 가능한지 확인

## 템플릿·문구 뱅크·예시

### 웰컴 시퀀스 구조 템플릿
```
[1통] 가입 직후 — 목적: 소개·공감 (판매 언급 0)
  - 나는 어떤 사람인가 / 왜 이 뉴스레터를 시작했나 / 당신이 겪고 있을 고민에 공감
  - 제목 톤: 개인적·다정 (예: "안녕하세요, 저를 소개할게요")
[2통] 가입 2~3일 후 — 목적: 가치 증명
  - 내가 줄 수 있는 도움, 노하우·정보를 구체적 예시로
[3통] 가입 5~7일 후 — 목적: 자연스러운 제안
  - 처음으로 제품·서비스 소개
```

### 세그먼트별 메시지 매핑
```
신규 구독자 → 나를 소개하는 내용
오래된 구독자 → 깊이 있는 정보 / 프로모션
링크 클릭 이력 있음 → 더 구체적인 정보 (같은 주제 후속)
클릭 이력 없음 → 가볍고 흥미를 끌 콘텐츠
구매 고객 → 감사 + 재구매 유도
잠재 고객 → 신뢰를 쌓는 정보성 콘텐츠
```

### 리스트 헬스 루틴
```
조건: 최근 3개월 이상 오픈 0회 → "휴면" 태그
→ 재참여 메일 1회: "저희 소식 계속 받아보실래요?"
→ 반응 O: 활성 구독자로 복귀
→ 반응 X: 정기 발송 리스트에서 제외 (삭제 X, 별도 분리 보관)
주기: 분기 1회
```

### A/B 제목 쌍 설계 규칙
```
A: 숫자/구체 정보 강조형
B: 질문형 (또는 궁금증 유발형)
→ 두 제목은 확실히 다른 접근. 과장 금지(내용과 일치).
→ 승자 판단은 오픈율, 최종 평가는 클릭률·구매까지.
```

### 사례(실패 → 교훈)
- 스팸함 갇힘: 오픈율 15% 몇 달 → 지인 "그 메일 못 받았는데?" → 도메인 인증 후 2주 만에 28%.
- 오픈율 낮다고 발송 빈도 증가 → 스팸 신고 확률↑, 평판 악화.
- 테스트 메일을 자주 주고받던 내 주소로만 확인 → 신규 구독자 메일함 판정과 다름.
- 구매 고객용 프로모션을 신규 구독자에게까지 전체 발송 → 구독 취소 급증.
- 세그먼트 10개 이상 → 콘텐츠 제작 감당 불가 → 3~4개로 재정리.
- 자극적 제목으로 오픈율↑ 그러나 클릭·구매↓.
- 도메인 갱신 과정에서 DKIM 레코드 누락 → 오픈율 급락.
- 자동 후속 메일이 종료된 프로모션 안내 → 월 1회 점검 원칙.

## 수치·기준값
- 구독자: 50명 → 1,200명 (약 8개월)
- 오픈율: 15% → 28%(도메인 인증 약 2주 후) → 38%
- 업계 오픈율 기준: 20% 평균, 30% 이상 꽤 잘함
- 첫 구매 전환율(신규 구독자): 3% → 11% (거의 4배)
- 이메일 매출 기여도: 전체 매출의 22%
- 이메일 업무 시간: 주당 5시간 → 40분 (초기 뉴스레터 1편 1~2시간)
- 첫 뉴스레터 만들어 발송까지: 반나절
- 제목 하나 고민: 30분(초기)
- DNS 반영: 몇 분~몇 시간, 전파 최대 24~48시간
- 인증 후 개선: 1~2주에 걸쳐 서서히
- 웰컴 간격: 가입 직후 / 2~3일 후 / 5~7일 후 (하루 간격 3통은 실패)
- 세그먼트: 시작 2그룹, 효과적 최소 3기준, 적정 3~4그룹, 10개+는 과다
- 세그먼트 시작 시점: 저자는 구독자 200명쯤(더 일찍 했어도 좋았음)
- A/B 테스트 표본: 전체의 20~30%, 비교 시간 보통 몇 시간
- 휴면 기준: 최근 3개월 이상 미오픈
- 점검 주기: 자동화 규칙 월 1회 / 휴면 정리 분기 1회 / MXToolbox 분기 1회
- 웰컴 시퀀스 통 수: 3통(2통~5통+ 가능)

## 흔한 실수 / 문제 해결
- 오픈율 낮을 때 콘텐츠부터 의심 → 먼저 "도달(스팸함)" 의심.
- "발송 성공" ≠ "받은편지함 도착"(스팸 필터에서 걸러질 수 있음).
- 메일 서비스마다 스팸 기준 다름(네이버 스팸, 지메일 정상 가능) → 국내 구독자 많으면 네이버·다음 기준 점검.
- 스팸함 상황에서 발송 빈도 증가 → 악화.
- 무료 메일 주소로 대량 발송 → 인증 불가.
- DMARC 처음부터 reject → 정상 메일까지 차단. p=none으로 시작.
- 레코드 타입 TXT/CNAME 혼동, 값 앞뒤 공백·따옴표 → 인증 실패.
- 도메인 갱신/이전/호스팅 변경 → DNS 레코드 누락 가능.
- 인증은 필요조건이지 충분조건 아님: 스팸 신고 많거나 무반응 주소로 계속 발송하면 평판 하락.
- 인증 후에도 스팸함 → 리스트 헬스 점검 + 콘텐츠 내 스팸성 단어·과도한 링크 확인.
- 전체 동일 발송 → 구독 취소 급증.
- 세그먼트 과다 분할 → 운영 불가.
- 웰컴 메일 1통 후 방치 → 전환율 낮음.
- 한 통에 소개+주제+제품 다 넣기 → 산만.
- 감으로 제목 결정, 한 번의 테스트로 단정, 비슷한 두 제목 테스트.
- 오픈율만 보기 → 과장 제목 함정.
- 정형화된 자동 메일 문구 → "자동 티" 피드백.
- 자동화 방치 → 종료 프로모션 안내.
- 휴면 구독자 정리에 미련 → 정리 후 오히려 도달률·오픈율 개선. "리스트는 크기보다 건강한 상태".

## FAQ 요점
- 도메인 없어도 시작 가능? → 발송은 가능. 대량 발송·인증은 도메인 필요. 구독자 쌓이면 마련 권장.
- 세그먼트는 몇 명부터? → 정해진 숫자 없음. 저자 200명쯤 시작, 더 일찍 해도 좋음. 적을 때부터 신규/기존만이라도.
- 웰컴 시퀀스 몇 통? → 3단계로 시작, 2통~5통+ 가능. "소개 → 가치 증명 → 제안" 흐름이 핵심.
- 오픈율 vs 클릭률? → 둘 다 중요, 장기 관계·매출은 클릭률.
- 자동화에 유료 플랜 필수? → 스티비 무료 플랜에서도 기본 자동화 일부 가능. 구독자 증가·세밀한 시나리오는 유료 필요할 수 있음.
- 인증했는데 스팸함? → 인증은 필요조건. 리스트 헬스, 스팸성 단어·과도한 링크 점검.
- 다른 분야에도? → 도달-공감-정교화-지속 흐름은 적용 가능, 세부는 조정.
- 왜 스티비? → 한국어 UI, 국내 메일 호환성 정보가 국내 커뮤니티에 많음. "독자가 한국에 있다면 툴도 한국 환경에 맞는 걸".

## 스토리 요약 (압축)
- SNS 팔로워 수천 명이었지만 매출 불안정, "이 팔로워는 내 것이 아니다" → 이메일로 전환, 구독자 50명(지인+SNS)으로 시작.
- 몇 달간 오픈율 15%, 원인은 스팸함 → 인증 후 개선 → 전체 발송 사고 → 세그먼트 → 다른 뉴스레터 벤치마킹으로 웰컴 시퀀스 → A/B → 업무 과다 → 자동화.
- 메시지: 속도보다 방향, 숫자 뒤의 사람을 기억.
