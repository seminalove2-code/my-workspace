# 상세페이지 (팔리는 40분)

상세 근거: `playbooks/04-detail-page.md` (문구 뱅크·체크리스트), `playbooks/06-ebook-sales.md` (크몽/래피드 상세페이지 순서·디테일 10가지).

## 1. 재료 모으기 (사용자에게 받는 것)
- 커리큘럼/목차 → Claude가 각 항목 옆에 **"이 강의(챕터)가 끝나면 ~할 수 있어요"** 한 줄씩 붙인다.
- 후기 → 3유형으로 3개 선별: 구체적 변화형 / 비슷한 상황형 / **숫자 포함형(있으면 무조건)**. **후기를 절대 지어내지 않는다.** 없으면 "왜 만들었는지 + 겪은 시행착오"를 사용자에게 받아 그 자리에 넣는다(템플릿 2 방식). 후기 수집용 질문 5개(부록 8)도 제안.
- 레퍼런스 페이지(선택) → **구조(배치 순서)만 참고, 문구·색감은 따라 하지 않는다.**
- 판매 채널(크몽/래피드/탈잉/클래스101), 가격, 브랜드 느낌 단어 1개(없으면 "신뢰감" 등 제안).
`output/ebooks/<제목>/`이나 `me/progress.md`에 이미 있는 정보는 다시 묻지 않는다.

## 2. 페이지 구성 (기본 뼈대)
1. **첫 화면**: 커리큘럼 나열 ❌ → "이걸 사면 무엇이 달라지는지" + 숫자 하나 + (크몽이면) 가격·핵심 혜택이 스크롤 없이 보이게. 헤드라인은 동사로 끝나게(명사로 끝나면 자료처럼 읽힘). 부록 8 헤드라인 10개 틀 활용.
2. **이런 고민 있으시죠?** (질문형 첫 문장) + **이런 분께 추천합니다** (3초 안에 "내 얘기"로 느끼게)
3. **이렇게 해결됩니다** (프레임워크/결과물)
4. **목차 미리보기** (이미지처럼 보이는 카드, 3개 이상) — 각 항목에 "끝나면 ~할 수 있어요"
5. **후기** (숫자 후기 맨 위, 페인포인트 옆에 짝지어 배치) — 래피드는 후반부에 구매자 후기 스크린샷 자리
6. **만든 사람** (탈잉이면 앞쪽으로 — 계기 짧게)
7. **구매 혜택 / 보너스 / 가격** (끝자리 900원), 업데이트 이력("YYYY년 M월 개정"), CTA 버튼(부록 8 CTA 10개)
8. FAQ 3개 (환불·받는 방법·대상)

채널별: 크몽 = 첫 화면 가격+혜택 / 탈잉 = 강사 신뢰를 앞으로 / 클래스101 = 커리큘럼 상세.

## 3. 만들기
- **HTML로 직접 제작**: 모바일 우선 단일 HTML(`output/pages/<제목>.html`). 큰 글씨, 가격·구매 버튼이 모바일 스크롤 안에서 잘 보이게, 표·이미지가 화면 밖으로 안 잘리게. 사용자가 원하면 Artifact로 게시해 링크를 주고, 미리캔버스/캔바용 섹션별 문구 파일(`<제목>-문구.md`)도 같이 만든다.
- **Claude Design용 프롬프트**도 함께 준다(사용자가 그쪽을 쓰고 싶을 때):
  ```
  [커리큘럼 붙여넣기] [후기 3개 붙여넣기] [참고 페이지 캡처]
  "이 강의를 판매하는 상세페이지를 만들어줘. 첫 화면에는 커리큘럼 나열이 아니라, 이 강의를 들으면 무엇이 달라지는지부터 보여줘. 톤은 실전적이고 친근하게 해줘."
  ```

## 4. 다듬기 규칙 (사용자가 수정 요청할 때)
- 통째로 다시 만들지 않는다. 짚은 섹션만 고치고 나머지는 그대로 유지.
- 한 번에 하나씩, 중요한 것부터. 첫 화면이 심심하면 숫자나 구체적 결과 하나 추가.

## 5. 발행 전 체크 (부록 5) — 결과와 함께 체크 표시해서 보여 준다
- [ ] 첫 화면에 "무엇이 달라지는지"가 보이는가
- [ ] 후기 중 최소 1개는 숫자 포함 (없으면 저자 경험으로 대체했는가)
- [ ] 레퍼런스에서 가져온 건 구조뿐인가
- [ ] 가격·구매 버튼이 모바일에서 잘 보이는가 / 글씨 크기 / 잘림 없음
- [ ] 이 페이지만 보고 내용을 짐작할 수 있는가 (5초 테스트)
- [ ] 경쟁 상품 문장·색감을 따라 한 곳이 없는가
- [ ] 다음에도 쓸 수 있게 저장했는가 (`output/pages/`의 HTML이 디자인 시스템 역할 — 다음 상품은 "지난번과 같은 톤으로" 이 파일을 기반으로)
- [ ] 채널 성격에 맞게 강조 포인트를 조정했는가

끝나면 `me/progress.md` 갱신, 커밋·push. 다음 단계로 `ebook-sales`(등록·가격·후기)를 제안.
