# 전자책 6단계 제작

상세 근거: `playbooks/03-threads-knowledge-startup.md` (§14 6단계, 프롬프트 11~20, 금지사항).

## 원칙
- **인터뷰 없이 바로 쓰지 않는다.** 재료가 부실하면 알맹이 없는 책이 된다.
- 주제는 "내가 보여주고 싶은 것"이 아니라 **"고객이 오늘 밤 당장 해결하고 싶은 단 하나의 문제"**.
- **선출시 후보완**: 100페이지 한 달 대신 20~30페이지로 먼저 내고, 반응 보고 업데이트.
- 계정 정체성과 맞는 주제인지 확인(예: AI 부업 계정에서 투자 책 ❌).
- 사용자 경험을 지어내지 않는다. 경험이 부족한 부분은 사용자에게 묻고, 사용자가 "가상 사례로 채워줘"라고 하면 그때만 '예시'임이 드러나게 채운다. (원본의 제미나이 꼼수에 해당)

## 진행 (작업 폴더: `output/ebooks/<짧은-제목>/`)

1. **재료 인터뷰** — `me/profile.md`, `me/progress.md`를 먼저 읽고, 빈 것만 한 번에 묻는다:
   타겟 독자 / 시작한 계기 / 초반 시행착오 3가지+ / 흐름이 바뀐 결정적 사건 / 나만의 원칙 5~7가지 / 증명할 숫자 / 독자에게 한마디.
   → 표로 정리해 `00-재료.md`에 저장.
2. **프레임워크화** — 경험을 3~6단계 프로세스로 구조화 + 이름 후보 3개("OO 공식"). 사용자가 고른다(고르기 귀찮다 하면 1번으로 진행). 이름 붙은 공식이 신뢰를 준다.
3. **목차** — 8개 챕터. 삽질담은 초반, 역전의 순간은 중반, 핵심 공식은 후반. 챕터마다 소제목 3~4개 + 핵심 한 줄 메시지. `01-목차.md`.
4. **챕터 집필** — 한 챕터씩 `ch01.md`… 로 쓴다. 브리핑:
   선배가 코칭하는 톤 · 독자는 [구체적 타겟] · 사용자의 실제 경험을 30% 이상 · 2인칭 대화체(~해요) · "첫째, 둘째, 셋째" 같은 AI스러운 나열 금지 · "~할 수 있습니다/따라서/결론적으로" 금지.
   챕터를 쓰기 전에 그 챕터에 넣을 경험 장면이 재료에 없으면 한 줄만 물어본다.
5. **챕터 끝 박스** — 각 챕터 끝에 `[핵심 요약]`(3줄 이내) + `[오늘의 실천 미션]`(오늘 바로 할 것 1개). 프롤로그는 "저도 처음엔..." 형태.
6. **워드(.docx) 완성** — 표지 / 목차 / 챕터별 페이지 나누기. 메인 컬러 1개로 챕터 제목·소제목 통일, 요약 박스 = 메인 컬러 연한 배경 + 테두리, 실천 미션 박스 = 보조 컬러 테두리. `anthropic-skills:docx` 스킬로 만든다.
7. **마무리** — 사용자에게 "처음부터 끝까지 한 번 읽고, 실제와 다른 부분만 고쳐 주세요"라고 안내(필수 단계라고 원본이 강조). 가격은 `ebook-sales` 스킬로, 판매 문구는 `detail-page` 스킬로 넘긴다.

## 확장 상품 (요청 시)
- **VOD**: 팔린 전자책 목차 → 5~7강, 강의당 10분 내외 대본. 화면에서 보여줄 부분을 `[화면: ...]`으로 표시. 촬영은 화면 녹화 + 마이크.
- **1:1 컨설팅**: "[시간] 안에 [무엇]을 진단하고 [결과물]을 드립니다" 한 문장으로 상품화. 첫 가격은 전자책의 2~3배. 사전 설문 문항 + 설문 받으면 "가장 먼저 점검할 3가지와 조언" 초안까지 만들어 준다. 시작 시점: 전자책이 꾸준히 팔리고 "직접 알려주실 수 있나요?" 문의가 반복될 때.
- **가격 라인업**: 저가(무료~1만원 리드마그넷) → 중가(5~10만원 전자책, 저자 99,000원) → 고가(컨설팅·VOD).

## 저장
진행할 때마다 `me/progress.md` 로드맵·기록을 갱신하고 커밋·push한다.
